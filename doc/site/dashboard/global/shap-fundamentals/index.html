Fundamentos de SHAP¶

SHAP es el marco de explicabilidad usado en el proyecto para atribuir una predicción de volatilidad implí­cita a las variables de entrada visibles del dashboard: tipo de opción, strike, subyacente, tiempo hasta vencimiento y tipo de interés. En términos prácticos, SHAP responde a una pregunta local: dada una muestra $x$, cuánto ha contribuido cada variable a mover la predicción desde un valor base hasta la volatilidad estimada por el modelo.

La motivación para usar SHAP en este proyecto es doble. Primero, los modelos candidatos no comparten una forma paramétrica: hay regresión lineal, árboles, boosting y redes neuronales. Una explicación basada solo en coeficientes no serí­a comparable entre familias. Segundo, el resultado debe ser defendible ante revisión técnica: las contribuciones deben sumar la predicción, estar definidas sobre una referencia explí­cita y permitir comparar explicaciones globales y locales con la misma semántica.

Descomposición aditiva¶

La forma general de una explicación SHAP es:

$$ f(x)=\phi_0+\sum_{j=1}^{p}\phi_j(x) $$

donde $f(x)$ es la predicción del modelo principal, $\phi_0$ es el valor base y $\phi_j(x)$ es la contribución atribuida a la feature $j$. En esta documentación, "contribución" no significa causalidad. Significa atribución de una diferencia predictiva respecto a una referencia definida por el fondo usado por el explicador.

El valor base $\phi_0$ se interpreta como la predicción esperada cuando todaví­a no se ha condicionado en las features concretas de la muestra. En el pipeline, el fondo se toma de una muestra del dataset de test configurada por shap_background_size. Para cada fila explicada, el codificador de explicabilidad reconstruye el espacio raw y llama al runtime del modelo, de modo que la explicación se calcula contra el mismo estimador que se evalúa y se publica en el bundle.

Relación con valores de Shapley¶

SHAP toma su fundamento de los valores de Shapley de teorí­a de juegos cooperativos. En ese marco, las features se interpretan como jugadores que cooperan para producir un pago: la predicción. El valor de Shapley de una feature es la contribución marginal media que aporta al añadirla a todos los posibles subconjuntos de features.

La forma conceptual es:

$$ \phi_j = \sum_{S \subseteq N \setminus {j}} \frac{|S|!(p-|S|-1)!}{p!} \left[ v(S \cup {j})-v(S) \right] $$

donde $N$ es el conjunto de features, $S$ es un subconjunto que no contiene $j$, $p$ es el número total de features y $v(S)$ es el valor esperado del modelo cuando se conocen las features de $S$. El término entre corchetes mide cuánto cambia la predicción al incorporar $j$ a una coalición ya conocida. El peso combinatorio promedia esa contribución sobre todos los órdenes posibles de entrada de las features.

Esta definición proporciona tres propiedades importantes:

Propiedad Interpretación en el dashboard
Eficiencia Las contribuciones suman exactamente la diferencia entre predicción y valor base.
Simetrí­a Dos features con el mismo efecto marginal reciben la misma atribución.
Dummy Una feature que no cambia el modelo no recibe contribución.
Aditividad En modelos aditivos, la explicación respeta la suma de componentes.

Estas propiedades son la razón por la que SHAP es más riguroso que una importancia basada únicamente en permutación global o en impureza de árboles. La importancia global por permutación contesta cuánto se degrada el rendimiento al alterar una columna; SHAP construye una contabilidad local de la predicción.

Aproximación por permutación en el proyecto¶

El repositorio usa shap.Explainer(..., algorithm="permutation"). Esta elección es deliberada: el pipeline debe explicar estimadores heterogéneos sin depender de un algoritmo especí­fico para árboles o redes. La aproximación por permutación trata el modelo como caja negra y evalúa predicciones bajo perturbaciones de las features.

En src/model2dashboard/artifact_builders.py, la función build_shap_artifacts construye:

Artefacto Muestra Uso
global_shap shap_explain_size filas de test Beeswarm, barras, dependence y heatmap global.
local_shap sample_option_size filas seleccionadas Waterfall local para muestras del dashboard.
Fondo shap_background_size filas Referencia contra la que se calcula $\phi_0$.

Cada fila se explica con:

$$ max_evals = 2p+1 $$

donde $p$ es el número de features de explicabilidad. En el estado actual del proyecto, esas features son las entradas raw visibles: OptionType, StrikePrice, UnderlyingPrice, TimeToExpiration y Rate. El uso de entradas raw mejora la lectura financiera de la explicación. El modelo real puede recibir features transformadas, pero el explicador reconstruye esas transformaciones al llamar al runtime.

Qué significa explicar variables raw¶

La decisión de explicar variables raw tiene una consecuencia importante. Si StrikePrice recibe una contribución alta, esa contribución resume el efecto que se produce al cambiar el strike raw y reconstruir las features derivadas que dependen de él. Por tanto, no debe leerse como el efecto aislado de una columna interna llamada logMoneyness. Debe leerse como el efecto agregado de la información de strike en el contrato explicado.

Lo mismo ocurre con UnderlyingPrice. En el entrenamiento, el subyacente participa en variables como logMoneyness y logForwardMoneyness. En SHAP, la contribución asociada a UnderlyingPrice se calcula en la interfaz raw y captura cómo la predicción cambia cuando la variable raw es conocida frente al fondo.

Esta capa de reconstrucción es útil para un tribunal técnico porque separa dos niveles:

Nivel Variables Uso
Interpretación financiera StrikePrice, UnderlyingPrice, TimeToExpiration, Rate, OptionType Explicación comunicable y auditable.
Entrada del estimador logMoneyness, sqrtTTEYears, rate, indicadores, interacciones Fidelidad predictiva del modelo.

Limitaciones de lectura¶

SHAP no prueba causalidad. Una contribución positiva de Rate no significa que subir tipos cause necesariamente más volatilidad en mercado; significa que, en el modelo entrenado y bajo la distribución de referencia usada, conocer ese valor de Rate desplaza la predicción hacia arriba respecto al valor base.

También hay que tener cuidado cuando las features están correlacionadas. En opciones, strike, subyacente, moneyness y vencimiento no son variables independientes en la práctica. La aproximación por permutación puede evaluar combinaciones que no son frecuentes en el mercado. Por eso el proyecto complementa SHAP con ALE, vecinos locales y checks de superficie. La explicación global no debe sustituir el diagnóstico de soporte empí­rico.
